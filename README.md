# UM 交接系统 · 无成人陪伴儿童

航班为无成人陪伴儿童登记送机人、接机人、航班号、座位与特殊照顾说明; 柜台核验送机人身份后签发交接单, 地面人员、乘务组、到达站人员**逐段签收**, 最终由授权接机人凭**授权码 + 本人证件**领取。

纯 Python 标准库实现(SQLite + http.server), 无第三方依赖。

## 一条命令启动

```bash
python3 run.py            # http://127.0.0.1:8000
python3 run.py --port 9000
```

首次启动自动: 建库(交接链不可覆盖) → 写入演示数据 → 生成虚构证件遮罩图 → 起服务。

演示数据含**改降样例**: `MU5110 北京PEK→上海SHA` 已改降 `南京NKG`, 案例 `UM-9B2C` 前两段在 PEK 签收, 后两段转到 NKG 继续; 其送机人手机号尾号 `000`, 模拟短信网关不可达, 自动触发"联系不上家属"异常。案例 `UM-7F3A`(CA1832) 为全新案例, 可从第 1 段完整走链。

## 测试

```bash
python3 -m unittest discover -s tests -v     # 26 个用例
```

覆盖需求点名的四类, 外加异常路径与最小可见:

| 需求 | 文件 |
|---|---|
| 顺序(上一环节未签收不得跳过) | `tests/test_ordering.py` |
| 旧码失效(授权变更即作废旧码) | `tests/test_auth_code.py` |
| 跨站权限(站点/岗位双重校验) | `tests/test_station_permissions.py` |
| 重复签收(并发只落一条) | `tests/test_duplicate_signoff.py` |
| 改降/证件不一致/联系不上家属/换班/最小可见 | `tests/test_exceptions.py` |

## 交接链与硬性规则

固定四段: `柜台→地面` → `地面→乘务组` → `乘务组→到达站` → `到达站→接机人`。

- **不可覆盖**: `handover_events / auth_changes / notifications` 由 SQLite 触发器禁止 UPDATE/DELETE; `(case_id, seq)` 唯一约束。
- **顺序**: 按 `seq` 严格递增, 跳段/越岗/越站一律拒绝; 第 4 段只能经"到达领取"核验授权码与证件后落链。
- **并发**: `BEGIN IMMEDIATE` 事务内检查 + 唯一约束, 两名工作人员同时交接只有一条有效记录。
- **授权变更**: 更换接机人 → 旧码 `REVOKED` 立即失效、签发新码、变更留痕、短信通知双方。
- **岗位最小可见**: 柜台见全量; 地面不见接机人; 乘务组只见代号/年龄/座位/照顾说明; 到达站见遮罩接机人; 授权码明文仅柜台/到达站可见。

## 七条应急路径(界面"应急路径"面板单独列出)

延误(改 ETA+通知) · 改降(交接链转备降站继续) · 接机人更换(旧码失效) · 证件不一致(领取拦截+通知送机人) · 儿童身体不适(通知家属/航医) · 交接人临时换班(改派下一责任人) · 联系不上家属(短信失败自动升级值班主管)。

## 结构

```
run.py               一条命令启动(建库/种子/遮罩图/服务)
umms/
  db.py              SQLite schema + 只增不改触发器
  service.py         签收/授权/异常/最小可见全部业务规则
  adapters.py        模拟航班适配器 + 模拟短信网关
  seed.py            演示数据(含 MU5110 改降样例)
  masks.py           虚构证件遮罩图(SVG)生成
  server.py          标准库 HTTP JSON API + 静态文件
static/              交接页(航空白/深蓝/高对比橙)
tests/               26 个 unittest 用例
```

界面顶栏可切换"当前岗位"(工作人员), 用以演示岗位最小可见与签收权限; 「航班运行」页可手动触发延误/改降。所有证件、手机号、航班均为虚构, 短信与航班动态由模拟适配器返回。
