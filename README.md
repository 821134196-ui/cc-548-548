# ✈ UMNR 无成人陪伴儿童 · 航班交接链（模拟系统）

为无成人陪伴儿童（UMNR）登记送机人、接机人、航班号、座位与特殊照顾说明；柜台核验送机人身份后签发交接单，地面人员 → 乘务组 → 到达站人员**逐段签收**，最终由**授权接机人凭证领取**。所有签收写入 SQLite 中一条**不可覆盖、不可跳段**的哈希交接链。

> 本系统仅用于流程演练：人员、证件号、短信、航班动态均为虚构模拟，证件图为本地生成的遮罩 SVG，不发起任何真实网络请求。

## 六类交付视图

打开任一交接单即可看到（按岗位最小可见裁剪字段）：

1. **旅客档案** — 儿童代号、航班、座位、照顾说明等；乘务看不到任何家属姓名/证件/电话；真实姓名令牌不对任何岗位界面下发。
2. **航段时间线** — 五段固定流程，每段明确 **时间 + 站点 + 地点**；当前等待段橙色高亮。
3. **交接签名** — 逐段留痕，列出签收人与链哈希。
4. **接机授权与变更** — 版本化授权码（库内仅存 SHA-256 哈希与提示码）；变更时**同一事务**内旧版置 `REVOKED`、新版发新码（模拟短信）。
5. **异常路径专区** — 七项异常（延误、改降、接机人更换、证件不一致、儿童不适、换班、联系不上家属），每项附标准应急处置路径，可登记处置与闭环（均为追加记录）。
6. **异常通知（模拟短信）** — 航班变动/授权变更时向送机人与接机人发送的模拟短信记录。

另附**到达领取**双验面板（授权码 + 现场证件号）与本地**遮罩证件图**。

## 核心业务规则（全部有测试覆盖）

- **顺序**：上一段未签收，签收下一段返回 `OUT_OF_ORDER`，不能跳过。
- **重复签收**：同段第二次签收返回 `ALREADY_SIGNED`；数据库另有部分唯一索引 `uq_signed_stage` 兜底，并发下晚到事务被拒。
- **两人同时交接**：`BEGIN IMMEDIATE` 写事务 + 唯一索引，同一段只落一条 `SIGNED`（见 `test/concurrent.test.js`，双进程真并发）。
- **旧码失效**：授权变更撤销旧版本后，旧码领取返回 `AUTH_CODE_INVALID`；旧接机人拿新码返回 `PICKUP_PERSON_MISMATCH`（人码绑定）。
- **跨站权限**：地面/柜台/接待严格按站隔离；改降后后续两段自动改由改降站账号操作，原目的站账号返回 `STATION_DENIED`；乘务组随机不做站点限制。
- **最小可见**：按角色字段白名单（`src/util.js` 的 `FIELD_VISIBILITY`）。
- **不可覆盖**：`handoff_events` / `exception_events` / `sms_messages` 触发器禁止 `UPDATE`/`DELETE`；事件以 SHA-256 哈希链首尾相接。

错误码速查：`OUT_OF_ORDER`（跳段）、`ALREADY_SIGNED`（重复）、`STATION_DENIED`（跨站）、`ROLE_DENIED`（岗位不符）、`AUTH_CODE_INVALID`（旧码/错码）、`ID_MISMATCH`（证件不一致）、`PARTY_MISMATCH`（非指定接收人本人）。

## 设计说明

- **签收人语义**：每段签收人是该段的**接收方本人**；交出方从上一段记录自动派生，首尾签名相接，不能自报交出方。
- **领取段**：到达站接待员（监交人，须属实际到达站）核验授权码哈希与接机人现场证件，双验通过才交付，授权随即置 `USED`、交接单 `COMPLETED`。
- **改降**：航班适配器推送 `DIVERTED` → 落异常 + 群发短信 → 时间线 seq3/seq4 的站点改到改降站，跨站规则随之切换。
- **仅模拟**：真实部署时把 `src/adapters.js` 换成航司运行系统与企业短信网关即可，领域服务接口不变。
